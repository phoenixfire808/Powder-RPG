# v1.15.24 — save-load companion fix + F12 HUD + F13 minimap

**Bug fix + UI.** Three deferred round-26 items ship together: old saves no longer
crash companion chat after load (plugin-state drift at the save boundary), the F12 HUD
Day row no longer overlaps the GOAL bar, and the F13 minimap is rewritten with biome
tinting, a player arrow, north marker, and coordinate readout.

## Summary

- **Verdict:** Bug fix (save-load) + UI polish (F12 HUD layout, F13 minimap). No
  gameplay-rule change, no native rebuild.
- **Scope:** `scripts/lua/rpg_plugins/companion.lua`, `scripts/lua/rpg_plugins/save.lua`,
  and `scripts/lua/rpg.lua`. Follows the v1.15.8 CONVENTION (plugin fixes roll into
  the next rpg.lua bump with a unified CHANGELOG entry).
- **Behaviour delta:** loading a save with an older `COMP` shape no longer leaves
  `chatQueue`/`queue` nil (companion chat polls safely); HUD Day line has its own
  background row and no longer collides with GOAL; version readout moves to
  bottom-left; minimap renders 50×30 tiles at 2 px with biome tinting, player arrow,
  north marker, and coord readout.
- **Risk:** low — save merge is additive (merge-don't-replace for `COMP` plus
  `_applyCompanionDefaults()` backfill); HUD/minimap are draw-only changes.

## Changes

Bullet pulled verbatim from `R.CHANGELOG[1]` at `scripts/lua/rpg.lua:207-209`:

- Old save files no longer crash companion chat after load (missing chatQueue/queue
  fields are merged and defaulted). F12 HUD: Day line has its own background row and
  no longer overlaps the GOAL bar; version readout moved to bottom-left. F13 minimap:
  50x30 tiles at 2px, biome tinting, player arrow, north marker, coord readout.

## Affected files

- `scripts/lua/rpg_plugins/companion.lua` — new `R._applyCompanionDefaults()` helper
  backfills missing `COMP` fields (`chatQueue`, `queue`, `mode`, position/velocity,
  hp, etc.) after load so `ipairs(C.chatQueue)` and chain enqueue paths never see
  nil tables.
- `scripts/lua/rpg_plugins/save.lua` — `doLoad` now **merges** `COMP` into the live
  table instead of blind-replacing it (`for fk, fv in pairs(v) do R.COMP[fk] = fv end`),
  then calls `R._applyCompanionDefaults()` so fields absent from older saves get sane
  defaults.
- `scripts/lua/rpg.lua` — F12 HUD: Day row gets its own `fillRect` background band;
  GOAL bar moved to top-right (`W-300`, `y=4`); version readout moved to bottom-left;
  `"enemies ON"` suffix dropped from the Day string. F13 minimap: `drawMinimap`
  rewritten — `sz=2` (50×30 tiles), biome/rec tint from `R.tiles[k].ex`, 5 px player
  arrow, north marker, coordinate readout, micro-legend.

## Migration notes

- **Plugin authors:** if your plugin saves state under `data.plugins`, consider an
  `R._applyXDefaults()` helper called from `save.lua`'s post-load path — same pattern
  as `R._applyCompanionDefaults()`. Merge-don't-replace is safer than blind
  `R[k] = v` when the live table already has runtime-only fields.
- **No save-format version bump.** Existing saves load forward; older `COMP` shapes
  are healed at load time. New saves are unaffected.
- **No native rebuild.** Lua-only change; hot-reload (`R.hotReloadRequested`) is
  sufficient once `R.VERSION` reads `1.15.24`.
- **Awaiting live confirmation:** bridge-verified on port 9876 (hot reload →
  `R.VERSION=="1.15.24"`, old-shape `COMP` + defaults → `ipairs(chatQueue)` ok,
  `companionChatPending` ok). Owner visual confirm still pending for F12/F13 layout.

## How-to-verify

1. **Pre-flight.** Confirm the HUD version readout (now bottom-left) reads `v1.15.24`.
   If it still shows an older version, hot-reload or restart — the change has not
   taken effect yet.
2. **Path 1 — save-load companion chat (the crash fix).** Load a save from before
   v1.15.24 (or any save where companion chat was active). Wait for or trigger a
   companion chat poll (`R.companionChatPending`). Expected: no Lua error about
   `ipairs` on nil `chatQueue`; companion lines appear normally. Before this fix,
   an older `COMP` shape could leave `chatQueue=nil` and crash on the next poll.
3. **Path 2 — F12 HUD layout.** Press **F12** to toggle the always-on HUD. With an
   active quest (GOAL bar visible) during daytime and at night: Expected: the Day
   line sits on its own background row and **does not overlap** the GOAL bar
   (GOAL is top-right). The version string reads bottom-left, not top-right.
   The Day string no longer appends `"enemies ON"`.
4. **Path 3 — F13 minimap.** Press **F13** to toggle the minimap. Walk across
   biome borders. Expected: 50×30 tile view at 2 px per tile; distinct biome/rec
   tinting; white player arrow (not a 4×4 square); **N** north marker; coordinate
   readout and micro-legend visible.
5. **Negative test — new world companion still works.** Start a fresh world, summon
   companion, trigger chat. Expected: identical behaviour to pre-fix new worlds —
   defaults path is a no-op when all fields already exist.
6. **Negative test — GOAL-less HUD.** Play with no active quest. Expected: Day row
   and gauges render without a stray GOAL placeholder; no new overlap regressions.
7. **Architecture verification.** Grep for `_applyCompanionDefaults` in
   `companion.lua` and confirm `save.lua:doLoad` calls it after the `COMP` merge.
   Grep `drawMinimap` for `sz=2` and the player-arrow draw path.
