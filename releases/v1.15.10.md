# Release v1.15.10 — bed respawn now also teleports companion + clears overhead (F9)

## Summary

v1.15.7 shipped F1 (`R.spawnPlayer()` teleports the companion to the fresh spawn point,
gated on `C.active` and not `C.dead`) and F8 (`R.clearAround()` re-added as a no-arg
version, 6-wide × 11-tall box above the spawn point). Both lived **inside**
`R.spawnPlayer()` — fine for the surface-respawn path (which is what `R.spawnPlayer()`
is), but they silently didn't run on the bed-respawn path (which goes through
`survival.lua`'s bed wrap, not through `R.spawnPlayer()`).

The consequence was an asymmetric bug: a player who dies deep and presses R respawns
cleanly (companion teleports + overhead is cleared), but the same player who dies deep
and bed-respawns leaves Aster stranded at the death site (or worse — stuck dead until
`REVIVE_DELAY` ticks past zero — defeating the v1.15.7 F1 fix entirely for every
survival-mode player who'd placed a bed). v1.15.10 closes the gap.

F9 follows the same fix pattern as v1.15.9's F5: extract the F1 + F8 behaviours into a
shared `R._teleportCompanionAndClear()` helper (analogous to the v1.15.9
`R._resetSpawnState()` helper), then call it from `survival.lua`'s bed wrap directly.
After this round, the **two-helper contract** for spawn-related behaviour is established:

- `R._resetSpawnState()` (from v1.15.9) — clears per-spawn stat state
  (`R.o2`, `R.gas`, `R.need.food` / `R.need.water`, `R.hurt` / `R.bloodLast`,
  `R.uvAccum` / `R.radAccum`, `R.hp`).
- `R._teleportCompanionAndClear()` (new in v1.15.10) — teleports the companion + clears
  the overhead region.

Both helpers are called by **both** spawn paths (`R.spawnPlayer()` body and the
`survival.lua` bed wrap). Future spawn-related additions should land on the helper layer,
not in either caller independently — that's the architectural lesson from this round.

## Changes

- **`R._teleportCompanionAndClear()` (new helper in `scripts/lua/rpg.lua`)** — the
  F1 (companion teleport, gated on `C.active` and not `C.dead`) + F8 (overhead
  clear-around, 6-wide × 11-tall) behaviours, combined into a single idempotent
  helper. Mirrors the v1.15.9 `R._resetSpawnState()` extraction pattern exactly.
- **`R.spawnPlayer()` refactored** — now calls `R._teleportCompanionAndClear()` as
  part of its existing F1 + F8 internal flow. Function-level behaviour is identical
  to v1.15.7 + v1.15.9 from the caller's perspective; only the location of the code
  changed (inline → helper call).
- **`survival.lua` bed-respawn now calls `R._teleportCompanionAndClear()`** — the
  bed wrap in `survival.lua` previously did NOT teleport the companion or clear
  overhead, because those behaviours were hidden inside `R.spawnPlayer()`. v1.15.10
  closes that gap by adding a call to the new shared helper at the appropriate
  point in the bed-respawn flow.
- **Architectural contract established**: every spawn path now uses both helpers, in
  the same order. Future spawn-related additions (a third helper, additional state
  resets, etc.) should be added to BOTH helpers + both call sites simultaneously,
  not patched into one caller independently.

## Affected files

**This is the THIRD multi-file release in `releases/`** after v1.15.8 and v1.15.9. By
the v1.15.8 CONVENTION note, this is now the documented default for any release that
combines a core change with a plugin-side hookup:

- `scripts/lua/rpg.lua` — `R._teleportCompanionAndClear()` defined as a new public-ish
  helper (`R._` prefix marks it "internal but accessible to plugins",
  same convention as `R._resetSpawnState()` from v1.15.9); `R.spawnPlayer()` body
  refactored to delegate to it in sequence with the existing call to
  `R._resetSpawnState()`. No signature change to the public `R.spawnPlayer()`.
- `scripts/lua/rpg_plugins/survival.lua` — bed-respawn wrap (the function the bed
  invokes on player wake) now calls `R._teleportCompanionAndClear()` after the
  existing v1.15.9 `R._resetSpawnState()` call. Both helpers fire on the bed path
  now; the bed's wake experience matches the surface's R-press experience.
- `scripts/lua/rpg_plugins/companion.lua` — **not touched** at v1.15.10 time. The
  v1.15.7 F1 and v1.15.8 F2 / F3 companion-side fixes are unaffected — they compose
  with the helper rather than conflict with it. `companion.lua`'s own state is
  reset/written only by the F1 block now living inside the new helper.

## Migration notes

None for the fix itself — pure structural refactor + a long-standing bug being
closed. No save-format change, no config change, no behaviour change beyond the bug
being fixed. `R.spawnPlayer()` keeps the same signature, the new
`R._teleportCompanionAndClear()` helper matches the naming convention of the v1.15.9
`R._resetSpawnState()` helper (which plugins weren't relying on either, since they
didn't exist before v1.15.9), and no breaking change.

**Architecture note for plugin authors**: from v1.15.10 onward, any plugin that needs
to do spawn-time work (`R.spawnPlayer()`-like or bed-wrap-like) should call **both**
helpers in order:

```lua
R._resetSpawnState()                 -- v1.15.9 stats reset
R._teleportCompanionAndClear()        -- v1.15.10 companion + overhead
```

Skipping either one means the spawn path silently regresses on what the helpers fix.

## How to verify

This closes the **"drift between core `spawnPlayer` and `survival.lua` bed wrap" bug
class**. v1.15.9's F5 fixed the `R._resetSpawnState` drift; v1.15.10's F9 fixes the
`R._teleportCompanionAndClear` drift. Both spawn paths now share the same per-spawn
work via the two-helper contract.

**Path 1 — Surface respawn (v1.15.7 + v1.15.9, must still work):**

1. Build or update to v1.15.10.
2. Spawn a world, let the companion join you. Walk deep underground (so she's actively
   following at distance). Drop a mess in the air directly above your surface spawn
   point (shoot some fire, generate a noxious gas cloud).
3. Die. Press **R** (or Esc → Respawn at surface) to respawn.
4. Confirm: Aster is standing right next to you at the surface spawn point (F1
   still works on the surface path), AND the air around you is clean (F8 still
   clears the surface path overhead).
5. *This is the v1.15.7 + v1.15.9 test -- must still pass after v1.15.10;
   confirms the helper extraction didn't regress anything on the surface path.*

**Path 2 — Bed respawn (v1.15.10, the new fix):**

1. Build or update to v1.15.10.
2. **Place a bed on the surface first** (somewhere safe — outside, in the open).
3. Same setup as Path 1: companion joins, walk deep underground with overhead mess
   to clear later.
4. Die. Your respawn path goes through the bed (not the surface) because you have
   one placed.
5. Confirm: Aster is standing right next to you at the bed wake point (NEW — before
   this fix, she was stranded at the death site), AND the air directly above the
   bed wake point is clean (NEW — before this fix, the overhead clear-around only
   ran on the surface path, so the bed wake could leave fire/gas hanging overhead).
6. Before this fix: Aster was stranded at the death site (or stuck dead until
   `REVIVE_DELAY` ticks past zero). After this fix: she follows you to the bed
   wake point and stays active.

**Negative test (companion-deaths-respect):**

1. Let the companion actually die (drop her in lava, let an enemy one-shot her).
2. Respawn via either path (surface or bed).
3. Confirm: she does NOT teleport (gate on `C.dead` still holds inside the helper,
   preserving the v1.15.7 F1 negative-test guarantee). The helper is idempotent on
   the "alive companion only" rule; if the helper ever silently dropped the gate,
   this test would catch it.

**Cross-version regression check (helper extraction is structural-only):**

1. Diff `R.spawnPlayer()`'s v1.15.10 body against the v1.15.9 inline-F1+F8 version.
2. Confirm same fields are reset to same values; only the location of the code
   changed (inline → helper call). Confirms the extraction is structural-only and
   doesn't silently drop a step.

**Architecture verification (meta-level):**

1. Look at the helper call order: in `R.spawnPlayer()` and in the `survival.lua`
   bed wrap, both should call `R._resetSpawnState()` first then
   `R._teleportCompanionAndClear()` second, in the same order.
2. The two helpers expose a clean separation: stats (`_resetSpawnState`) vs.
   physical placement (`_teleportCompanionAndClear`). Any future spawn-related
   addition lands on whichever helper is its category.
