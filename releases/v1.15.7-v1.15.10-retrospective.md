## The pattern — respawn-path drift

All four versions in this cluster fix variations of the same bug class: **a behaviour
that lived inside the surface respawn path silently did not run on the bed respawn
path.** Each fix made the surface path better; only the next round's cross-version
check noticed the bed path was drifting from the same behaviour.

The mechanism was the same every time:

1. The behaviour (companion teleport, overhead clear-around, per-spawn state reset)
   was added inline inside `R.spawnPlayer()`.
2. `R.spawnPlayer()` is what the surface respawn path calls.
3. The bed respawn path in `survival.lua` goes around `R.spawnPlayer()` — it has
   its own wrap function that does the teleport + spawn-position-thing + bed-HP-rule
   independently, and only reuses specific named bits from `R.spawnPlayer()` that
   were made available to plugins.
4. Anything inlined inside `R.spawnPlayer()` therefore ran on surface-respawn and
   not on bed-respawn, with no compile-time warning and no visible symptom in
   light testing.

**Why it took four rounds to surface all the variants:**

- **v1.15.7** added F1 + F8 directly into `R.spawnPlayer()`. The drift was already
  there; nobody noticed yet because the test plan was the surface path only.
- **v1.15.8** was unrelated to spawn paths (companionKill queue + newworld reset +
  CONVENTION note). It just happened to be the first multi-file release, which
  set up the convention for future cross-file work.
- **v1.15.9** closed the **stats** axis of the drift. v1.15.4 had added the
  per-spawn state reset (`R.o2`, `R.gas`, `R.need.food/water`, `R.hurt/bloodLast`,
  `R.uvAccum/radAccum`, `R.hp`) inline in `R.spawnPlayer()`. v1.15.9 noticed the
  bed path wasn't getting it, extracted the block into `R._resetSpawnState()`,
  and called it from both paths. This was the FIRST fix-shape that addressed
  drift, but only for the stats axis.
- **v1.15.10** closed the **companion + overhead** axes of the same drift.
  v1.15.7's F1 + F8 had been added inline in `R.spawnPlayer()`, so the bed path
  missed them just like the stats. v1.15.10 extracted F1 + F8 into a second helper
  `R._teleportCompanionAndClear()` and called it from both paths.

**The two-helper contract that emerged:**

```lua
R._resetSpawnState()                  -- v1.15.9 stats reset
R._teleportCompanionAndClear()        -- v1.15.10 companion + overhead
```

These two helpers are now the canonical per-spawn work, called from BOTH `R.spawnPlayer()`
and the `survival.lua` bed wrap in the same order. Future spawn-related additions land
on whichever helper fits the category, not in either caller independently — that's the
architectural lesson from the cluster.

## Cross-version relationships (the family tree)

- **v1.15.7 → v1.15.9 → v1.15.10** form the respawn-helper trio: v1.15.7 added the
  inline behaviour, v1.15.9 extracted the stats half, v1.15.10 extracted the
  companion + overhead half. Same architectural pattern (extract-into-shared-helper,
  call from both paths), one round each axis.
- **v1.15.4 → v1.15.9 → v1.15.10** form the COMPLETE bug-class fix: v1.15.4 added
  the inline reset (surface only), v1.15.9 closed the stats axis on the bed path,
  v1.15.10 closed the companion + overhead axes on the bed path. After v1.15.10,
  bed-respawn and surface-respawn are behaviorally identical.
- **v1.15.8 (CONVENTION note)** → every release after it: rpg.lua owns `R.VERSION`,
  plugin fixes roll into the next rpg.lua bump. v1.15.9, v1.15.10, and any future
  cross-file fix all follow this convention by default — including the THIRD
  multi-file release (v1.15.10) being a natural pattern at this point, not a
  one-off.

## What to watch for next time

The cluster was expensive in terms of rounds — 4 versions, 4 bug-fix rounds, all
fixing variations of the same drift. Three process changes would catch the drift
faster on the next round of spawn-related work:

1. **Treat `R.spawnPlayer()` as a public-ish entry point, not the surface-path's
   private helper.** If a new per-spawn behaviour is added inside `R.spawnPlayer()`,
   the bed path (and any future spawn path — mount, portal, save-load-recovery,
   etc.) needs an explicit hookup in the same commit, not in a follow-up round.
   Cheap rule: any change to `R.spawnPlayer()` body should grep for other callers
   of spawn-time work (`survival.lua`'s bed wrap is the only one today, but future
   spawn paths could grow) and update them in lockstep.
2. **Test BOTH paths before shipping.** v1.15.7's F1 verification was surface-only
   -- it confirmed the companion follows on R, but never tested what happens when the
   player has a bed placed. v1.15.9 added the bed-path test as part of its own fix;
   v1.15.10 added it again as part of its own. The two-path test should be the
   default for any spawn-related change, not the opt-in.
3. **Document the two-helper contract alongside the new helper, not in a
   follow-up.** v1.15.9 introduced `R._resetSpawnState()`; v1.15.10 introduced
   `R._teleportCompanionAndClear()` and (in the same round) documented the
   contract. Earlier rounds had no doc on "these are the spawn-time primitives --
   use these, don't patch the callers independently" until the third release in
   the cluster. Plugin authors reading rpg.lua in v1.15.10 see the doc; plugin
   authors reading v1.15.9 had to guess.

## Post-retrospective tail (v1.15.11 + v1.15.12)

The respawn-path-drift saga closed at v1.15.10. The two releases that
followed are post-retrospective and out of scope for the cluster above:

- **[v1.15.11](v1.15.11.md)** -- QoL: `'Sunburnt' chat cooldown` via
  `R.lastSunburnAt` (1800 frames / ~30 s ceiling; damage tick continues
  every 300 frames as before). Single-file rpg.lua change.
- **[v1.15.12](v1.15.12.md)** -- F10 cosmetic: trees no longer float
  above the grass (1-px air gap at every tree base, fixed via
  `wy <= t.s` in `genBase` trunk loop). Single-file rpg.lua change.

Neither round touches the respawn path or the spawn-time helpers
(`R._resetSpawnState()` + `R._teleportCompanionAndClear()`) established
by v1.15.9 + v1.15.10. They are the natural QoL / cosmetic tail that
follows once the bug-class is closed: the cluster ended on
"behavioural parity between surface and bed respawn"; the tail lands
on separate, unrelated classes (chat cadence, world rendering).

- **[v1.15.24](v1.15.24.md)** — save-load companion fix (`COMP` merge +
  `_applyCompanionDefaults()`) plus F12 HUD layout and F13 minimap. Different
  boundary (save file vs respawn path) but the same "state drift when one path
  forgets to reset/backfill" pattern the respawn cluster taught.
