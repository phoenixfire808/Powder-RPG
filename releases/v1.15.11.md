# v1.15.11 — Sunburn chat cooldown

**QoL.** One bug class, one round, one file. The recurring "Sunburnt (X% UV
exposure) — get some shade" message was firing every 5 s while you stood
outdoors with `uvAccum > 70`. The 1-HP damage tick keeps firing every 300
frames as before — that's the actual gameplay signal. The chat message was the
noise. This separates the two: damage tick continues at the original cadence,
chat message repeats at a 30-second ceiling instead.

## Summary

- **Verdict:** QoL — single-file change, no engine or plugin risk.
- **Scope:** `scripts/lua/rpg.lua` only. No plugin changes, no native rebuild.
- **Behaviour delta:** outdoors exposure with `uvAccum > 70` now logs the
  sunburn warning at most once every ~30 s (1800 frames) while damage ticks
  continue every 300 frames as before.
- **Risk:** zero functional risk — damage tick unchanged, only the chat-message
  cooldown was introduced. The `R.lastSunburnAt` field is a fresh addition
  and resets to `nil` on every new world via the existing frame-stamped
  cooldown reset list at `generateWorld`, so it can't bleed across saves.

## Changes

Bullet pulled verbatim from `R.CHANGELOG[2]` at `scripts/lua/rpg.lua:206-208`:

- QoL: `'Sunburnt (X% UV exposure) -- get some shade'` no longer spams the
  chat every 5 s while you stand outdoors with `uvAccum > 70`. Added
  `R.lastSunburnAt` cooldown: the 1-HP damage tick still fires every 300
  frames as before, but the chat message only repeats every ~30 s (1800
  frames). Reset to `nil` on new world (added to the existing frame-stamped
  cooldown reset list at `generateWorld`).

## Affected files

- `scripts/lua/rpg.lua` — sole change.
  - New field `R.lastSunburnAt` (frame counter for chat-message cooldown).
  - Sunburn-tick guard now reads `R.lastSunburnAt` and skips the chat message
    unless `frame - lastSunburnAt >= 1800` (or `lastSunburnAt` is `nil`,
    which it is on the first tick after a fresh world).
  - Damage tick (`R.hp -= 1`) continues to fire unconditionally every 300
    frames, regardless of the chat cooldown.
  - `R.lastSunburnAt` added to the frame-stamped cooldown reset list at
    `generateWorld` (the same reset list that owns `R.lastDeathAt`,
    `R.lastFallAt`, etc.), so a new world starts with it `nil` and the
    first outdoor tick fires the chat message normally.

## Migration notes

- **No plugin changes required.** None of the cooldown-reset list entries
  are owned by plugins; the `R.lastSunburnAt` addition lives entirely inside
  `rpg.lua`.
- **No save-format changes.** `R.lastSunburnAt` is a runtime-only field; it
  resets on every world-load via the same `generateWorld` path that already
  resets every other frame-stamped cooldown. Existing saves do not need to
  be touched; the new field simply starts `nil` on next load and the first
  sunburn tick fires the chat as before.
- **No HUD / UI changes.** This is a chat-message-cadence fix only. The
  damage-tick behaviour, the always-on HUD (`Deaths: N`, version readout),
  the inventory panel, the crafting panel, and the Esc/Options menu are
  all unchanged.
- **For plugin authors:** the existing frame-stamped cooldown reset list at
  `generateWorld` is the documented place to add any future
  `R.last…At`-style fields. If you add a cooldown field inside your plugin
  and want it to reset on a new world, append it to that list in a follow-up
  rpg.lua bump (per the CONVENTION note established in v1.15.8).

## How-to-verify

1. **Path 1 — outdoors exposure, message cadence.** In a fresh world, walk
   the player outdoors during daytime (the always-on HUD shows the version
   readout top-right — confirm it reads `1.15.11`). Stand still in
   unsheltered daylight until `uvAccum > 70` and the first "Sunburnt …"
   chat message appears. Continue standing still in the sun. Expected: the
   1-HP damage tick fires every 300 frames as before (HP steadily drains);
   the chat message repeats **at most every ~30 s**, not every 5 s. Before
   this fix, the chat would re-fire roughly every 5 s (300 frames); after
   this fix, expect at most six chat messages per 3 minutes of standing
   still outdoors (vs. ~36 before).
2. **Path 2 — taking shelter resets nothing, damage still works.** After
   the first chat message has fired, walk under a tree canopy or into a
   cave. UV exposure should pause (no further "Sunburnt" ticks while
   sheltered). Walk back out into the open sun. Expected: the chat message
   is silent for the remainder of the 30-second cooldown window from the
   last message, then resumes normally. Damage ticks resume immediately on
   re-exposure.
3. **Negative test — `R.lastSunburnAt` does not block the damage tick.**
   The 1-HP damage tick is independent of the chat cooldown. Standing
   outdoors for 5 minutes straight with `uvAccum > 70` should drain HP
   continuously at the original 300-frame cadence, not be held off by
   chat-message cooldown. If damage ever pauses when UV is high, that's a
   regression — `R.lastSunburnAt` is gated on the chat write only, not on
   the HP decrement.
4. **Negative test — fresh world resets the cooldown.** Load a world,
   stand outdoors long enough to fire the chat message once, save & quit
   to title, click "Play" / "New World". Walk the new world's player
   outdoors during daytime. Expected: the first sunburn tick fires the
   chat message immediately (cooldown is `nil` for the new world), not
   silent for 30 s. If the chat is silent on the first tick after a fresh
   `generateWorld`, that's a regression — `R.lastSunburnAt` should be
   reset to `nil` by the frame-stamped cooldown reset list.
5. **Cross-version regression check — companion + bed respawn.** The
   v1.15.7 / v1.15.9 / v1.15.10 respawn-path fix cluster is unrelated to
   sunburn, but worth a quick smoke test: place a bed (if you're on the
   survival.lua path), die to a known cause, and confirm companion
   teleports to the new spawn + overhead region clears + stats reset.
   This should be unchanged from v1.15.10 — no regression introduced by
   the cooldown addition.
6. **Architecture verification — cooldown reset list contains the new
   field.** Open `scripts/lua/rpg.lua` and grep for `R.lastSunburnAt`.
   Expected hits: (a) the assignment to `R.frame` on every sunburn tick
   that actually writes the chat message, (b) one entry inside the
   `generateWorld` reset list alongside the other frame-stamped cooldowns.
   If either is missing, the round is incomplete.
