# Release v1.15.9 — bed respawn now clears death pollution (F5)

## Summary

v1.15.4 fixed "dying and respawning at the surface still poisons you on the new spawn",
because the same per-spawn state (`R.o2`, `R.gas`, `R.need.food` / `R.need.water`,
`R.hurt`, `R.bloodLast`, `R.uvAccum`, `R.radAccum`) — the death-pollution envelope that
gets you killed a second time after the first death — was being preserved through the
respawn.

The fix only landed on the **surface** respawn path. **Beds** (the other respawn path —
sleep through the night, wake up at a bed you've placed) kept the old buggy behaviour:
die to CO₂ underground, teleport to a bed, wake up still suffocating from the gas envelope
that followed the teleportation, HP drains a second time. Same bug class, different
spawn-entry-point.

v1.15.9 fixes the bed path by extracting the v1.15.4 reset block into
`R._resetSpawnState()` (a shared, idempotent helper) and calling it from both the core
`R.spawnPlayer()` and the new bed-respawn wrap in `survival.lua`. The two paths now share a
single source of truth for "what state does a fresh spawn look like", and any future spawn
path (a third one in a future release, a debug command, etc.) gets the right behaviour
just by calling the same helper.

## Changes

- **`R._resetSpawnState()` (new helper in `scripts/lua/rpg.lua`)** — the v1.15.4 reset
  block, now idempotent and callable from any spawn path. Sets `R.o2 = 100`, clears
  `R.gas.*`, fills `R.need.food` / `R.need.water` to 100, clears `R.hurt` /
  `R.bloodLast`, zeroes `R.uvAccum` / `R.radAccum`, and sets `R.hp = 100`. Magic Mirror's
  HP save-and-restore around the call still works — the helper only writes hp=100 when
  it's safe to do so (caller passes a `keep_hp = true` flag for the accessory case).
- **`R.spawnPlayer()` refactored** — now calls `R._resetSpawnState()` instead of
  inlining the reset block. Function-level behaviour is identical to v1.15.4 from the
  caller's perspective; this is purely a structural improvement so the same cleanup
  applies everywhere a spawn happens.
- **`survival.lua` bed-respawn now calls `R._resetSpawnState()`** — the bed-spawn wrap
  in `survival.lua` previously did NOT clear the death-pollution envelope. v1.15.9
  adds a call to the shared helper at the top of the bed-respawn flow, so a player who
  dies to CO₂ underground and respawns via bed wakes up in a clean envelope rather
  than the toxic one. Bed HP rule (`max(current_hp, 40)`) and bed-position teleport
  are **unchanged** — the only difference is the per-spawn state is now also wiped.

## Affected files

Like v1.15.8, this release touches BOTH `scripts/lua/rpg.lua` AND a plugin
(`scripts/lua/rpg_plugins/survival.lua`). That's now the documented default per the
v1.15.8 CONVENTION note rather than a one-off:

- `scripts/lua/rpg.lua` — `R._resetSpawnState()` defined as a new public-ish helper
  (`R._` prefix marks it "internal but accessible to plugins"); `R.spawnPlayer()` body
  refactored to delegate to it. No signature change to the public `R.spawnPlayer()`.
- `scripts/lua/rpg_plugins/survival.lua` — bed-respawn wrap (the function the bed
  invokes on player wake) now calls `R._resetSpawnState(keep_hp = true)` at the top of
  its flow, so the wake event also wipes the death-pollution envelope.
- `scripts/lua/rpg_plugins/companion.lua` — **not touched** at v1.15.9 time. The v1.15.8
  F1 + F8 companion-related fixes from the previous round are unaffected (and
  complementary — `R.spawnPlayer()` and the bed wrap both still flow through them).

## Migration notes

None. Pure bugfix + a small structural refactor on top of v1.15.4. No save-format
change, no config change, no behaviour change beyond the bug being fixed on the bed
path. `R.spawnPlayer()` keeps the same signature; `R._resetSpawnState()` is new but
plugins weren't relying on either the old inlined behavior or a previous `_resetSpawnState`
(it didn't exist), so no breaking change.

## How to verify

This is the **second bug-class fix for the same death-loop pattern** — v1.15.4 fixed the
surface respawn path; v1.15.9 fixes the bed respawn path. The test must exercise **both**
to confirm the cross-version pattern is actually closed:

**Path 1 — Surface respawn (v1.15.4, must still work):**

1. Build or update to v1.15.9.
2. Walk deep underground until the air thins and you start taking CO₂ suffocation
   damage. Confirm `R.o2` is low, `R.gas.co2` is non-zero (check the dev console), and
   HP is draining.
3. Die. Press **R** (or Esc → Respawn at surface) to respawn at the surface.
4. Confirm: `R.o2` reads 100, `R.gas.*` reads 0/cleared, HP reads 100, food / water
   read 100. The air around the respawn point reads clean on the hover tooltip.
5. *This is the v1.15.4 test — must still pass after v1.15.9; confirms the
   `_resetSpawnState` extraction didn't regress anything.*

**Path 2 — Bed respawn (v1.15.9, the new fix):**

1. Build or update to v1.15.9.
2. **Place a bed** on the surface first (somewhere safe — outside, in the open).
3. Walk deep underground until you're suffocating again — same death-pollution setup.
4. Die. Your respawn path now goes through the **bed** (not the surface) because you
   have one placed.
5. Confirm: same as Path 1 — `R.o2` 100, `R.gas.*` cleared, HP 100, food / water
   100. Wake up clean.
6. Before this fix: the bed-respawn flow left the death-pollution envelope intact, so
   you woke up in the bed still suffocating from the gas that killed you, and HP kept
   draining. After this fix: clean wake.

**Negative test (bed-HP rule still holds):**

1. Die at full HP (100) to something other than the death-pollution case — e.g. fall
   damage, enemy kill. Confirm `R.hp` is low (say, 0 → reset to 0 by the death
   handler) before respawn.
2. Respawn at the bed.
3. Confirm `R.hp` reads 40 (the v1.15.9 bed rule is `max(current_hp, 40)`, unchanged
   from v1.15.8). The bed's "wake up with at least 40 hp" behaviour still applies.
   (If `R._resetSpawnState` overrode hp when it shouldn't have in the bed path, this
   test would catch it.)

**Cross-version regression check:**

1. Diff `R.spawnPlayer()`'s v1.15.9 body against the v1.15.4 inline-reset version.
2. Confirm same fields are reset to same values; only the location of the code
   changed (inline → helper call). Confirms the extraction is structural-only and
   doesn't silently drop a field.
