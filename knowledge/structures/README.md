# Structure library: schema + loader (hand-off to @world)

Source and rationale: `knowledge/research-community-structures.md` (42 newly harvested community saves,
analysed offline via an isolated lab instance -- Drew's live game was never touched). 30 structures live in
this folder as `<id>.json`, generated by `scripts/gen_structures.py` (edit the Python, not the JSON directly,
and re-run it) and validated visually by `scripts/render_structures.py` (PNG previews in `knowledge/previews/`).

**I have not touched `world.lua` or any other plugin file.** Everything below is a spec plus a literal,
ready-to-paste Lua reference implementation for @world to drop in and adapt. Ping the hub if anything doesn't
fit `world.lua`'s actual internals as they exist by the time you read this -- happy to iterate.

## Why this shape

`world.lua`'s `gen(wx, wy)` hook contract (from `rpg.lua`): return an element name to place solid material,
`""` to force air (carves a hole), or `nil` to say "no opinion, keep whatever the base terrain / next hook
would have put there." `world.lua` already implements two structure kinds this way (`ruinHere`, `mineshaftHere`)
inside its `structureAt()` function, using a consistent pattern repeated for every feature in that file: a
per-category spacing constant, a cache table keyed by cell index, a `xxxAt(cellIndex)` function that rolls the
instance's parameters once and caches them, and a `xxxHere(wx, wy, d)` lookup that checks the 1-3 neighbouring
cells and returns a value or `nil`. The structure library below is the same pattern, generalized to load its
shapes from data instead of hand-coding each one, so new structures are a new JSON file, not new Lua.

## JSON schema

```
{
  "id": "surface_cabin_small",        // matches the filename
  "category": "surface" | "underground" | "deep" | "detail",
  "description": "...",               // human-readable, not used at runtime
  "biomes": ["forest","swamp","snow"] | ["any"],
  "depth_band": { "min": -4, "max": 2 },
  "rest_on_solid": true,              // see "Placement rule" below
  "erodible": true,                   // eligible for the generic erosion pass
  "rarity": 0.16,                     // relative weight within its category's eligible pool at a given roll
  "min_spacing": 260,                 // world-px; loader's per-category grid pitch should be >= the largest
                                       // min_spacing among structures competing for that grid (see Placement)
  "clearance": { "top": 2, "bottom": 0, "left": 2, "right": 2 },  // extra cells reserved around the footprint
                                       // when checking for overlap with a neighbouring roll (not drawn)
  "anchor": { "x": 7, "y": 12 },      // grid cell that maps to the placement's reference world point -- see below
  "width": 15, "height": 17,          // grid.length[0] and grid.length must match this
  "legend": { "F": "stone", "W": "wood", "G": "glass_colored", "V": "metal_old", ".": "air", " ": "keep" },
  "grid": [ "............... ", ... ],  // width chars x height rows, row 0 = top
  "loot": [ { "x": 5, "y": 5, "tier": 3, "note": "..." } ],   // grid-local cells worth a guaranteed reward; see below
  "variants": [ ],                     // reserved (mirroring etc.) -- none of the 30 use it yet
  "notes": "design rationale, sourced saves, sizing rationale"
}
```

**Legend values** are one of:
- `"air"` -- forces that cell empty (`gen` returns `""`), even underground/in solid rock. Carves a real cavity.
- `"keep"` -- transparent: `gen` returns `nil` for that cell, i.e. "I have no opinion, let the terrain (or an
  earlier-registered hook) decide." Used at footprint edges so e.g. a rubble pile or fence post doesn't stamp a
  hard rectangle of forced-air around itself.
- anything else is a **logical material token** (`wood`, `stone`, `brick`, `concrete`, `glass`,
  `glass_colored`, `metal`, `metal_old`, `bronze`, `iron_ore`, `coal`, `gold`, `copper`, `clay`, `crystal`,
  `plant`, `glow`, `bone`, `ice`, `snow`, `sand`, `water`, `lava`) -- resolved to a real element id at *load
  time* (once, not per pixel) through the `has()`-guarded table below, exactly mirroring `world.lua`'s own
  `ROCK`/`ROCK2`/`GRASS`/`UORE` locals. Never hardcode a possibly-absent custom element id in a structure file.

**Anchor rule.** `anchor` is the grid cell whose world position equals the placement's reference point
`(px, py)`, where a cell at grid `(gx, gy)` maps to world `(px + gx - anchor.x, py + gy - anchor.y)`.
- **surface** category: `py = surfaceAt(px)`, i.e. the first *solid* ground row (matches `world.lua`'s own
  `surf` variable: `wy < surf` is open air, `wy >= surf` is ground). By convention here, rows `>= anchor.y` are
  the structure's own grounded/embedded material (a foundation slab, a soil row, a footing) and rows `<
  anchor.y` are the above-ground body (walls, roof, posts). Concretely: if a structure explicitly draws its own
  ground-level material (a foundation, tilled soil), `anchor.y` **is** that row. If a structure just stands
  freely on implicit terrain with no drawn foundation (a tent, a crate stack), `anchor.y` is one past its lowest
  occupied row, so that row lands at `surf - 1` -- the row a standing player's feet occupy -- which is exactly
  where "resting on the ground" should read. `surface_cabin_small` and `surface_campsite` are worked examples
  of each case; read their `notes` fields.
- **underground / deep** categories: there is rock on every side, no ground/air asymmetry, so `anchor` is just
  "the grid cell aligned to the rolled placement point" -- most structures here anchor near floor-center for
  readability but it isn't load-bearing the way the surface rule is.
- **`surface_bridge_wood`** is the one deliberate exception: `rest_on_solid: false` and `anchor` marks the
  walking-deck height, because a bridge's placement rule is "spans a gap," not "sits on solid ground" -- see
  below.

## Placement rule (per structure, evaluated once at roll time, cached forever after)

Standard case (`rest_on_solid: true`): before accepting a roll at candidate `wx`, verify with the same
generator functions `world.lua` already has in scope (`surfaceAt`, `rockAt`/`caveAt` or `gen`) that:
1. the ground at `wx` (and `wx + width`, for wide structures) is solid at the reference row (no floating
   cabins over a cliff edge or cave mouth), and
2. the full footprint plus its `clearance` margin doesn't already overlap a previously-placed structure from
   this or an adjacent cell (check the same category's cache table for the 1-2 neighbouring cells).

`surface_bridge_wood` (`rest_on_solid: false`): instead verify a **gap** -- open air, cave, or water -- under
roughly the middle third of the span, with solid ground at both end piers. This is the one place the generic
engine below needs a structure-specific placement predicate; everything else uses the standard check.

`underground_ladder_shaft` (`rest_on_solid: false`): the shaft itself passes through open cave space by
design; only the *bottom* row needs a solid-ground check at placement time.

## Reference loader + placement engine (paste into world.lua, or a new required-by-concatenation module)

This is a complete, self-contained implementation in `world.lua`'s own style (same `hash3`/cache-table idioms).
It loads every `knowledge/structures/*.json` once (via `io.open` with an absolute path -- confirmed working at
runtime today: `rpg.lua`'s own `R.save`/`R.load` already read/write `D:/powder-toy/knowledge/rpg-save.json`
the same way), groups structures by category, and exposes one function:

```lua
Structures.at(wx, wy, surf, d, biome) -- returns element name, "", or nil, just like any gen sub-function
```

```lua
-- ===== minimal JSON decoder (object/array/string/number/bool/null; no comments, no trailing commas) =====
-- Self-contained on purpose so this module has zero dependency on save.lua's own private newJsonParser.
local function jsonDecode(s)
  local i = 1
  local function skip() while i <= #s and s:sub(i,i):match("%s") do i = i + 1 end end
  local parseValue
  local function parseString()
    i = i + 1; local buf = {}
    while true do
      local c = s:sub(i,i)
      if c == '"' then i = i + 1; break end
      if c == "\\" then
        local n = s:sub(i+1,i+1)
        local map = { n="\n", t="\t", r="\r", ['"']='"', ["\\"]="\\", ["/"]="/" }
        buf[#buf+1] = map[n] or n; i = i + 2
      else buf[#buf+1] = c; i = i + 1 end
    end
    return table.concat(buf)
  end
  local function parseNumber()
    local j = i
    while i <= #s and s:sub(i,i):match("[%d%.%-%+eE]") do i = i + 1 end
    return tonumber(s:sub(j, i-1))
  end
  local function parseArray()
    i = i + 1; local out = {}; skip()
    if s:sub(i,i) == "]" then i = i + 1; return out end
    while true do
      skip(); out[#out+1] = parseValue(); skip()
      if s:sub(i,i) == "," then i = i + 1 else break end
    end
    skip(); i = i + 1; return out
  end
  local function parseObject()
    i = i + 1; local out = {}; skip()
    if s:sub(i,i) == "}" then i = i + 1; return out end
    while true do
      skip(); local k = parseString(); skip(); i = i + 1 --[[ ':' ]]; skip()
      out[k] = parseValue(); skip()
      if s:sub(i,i) == "," then i = i + 1 else break end
    end
    skip(); i = i + 1; return out
  end
  parseValue = function()
    skip(); local c = s:sub(i,i)
    if c == '"' then return parseString() end
    if c == "{" then return parseObject() end
    if c == "[" then return parseArray() end
    if s:sub(i,i+3) == "true" then i = i + 4; return true end
    if s:sub(i,i+4) == "false" then i = i + 5; return false end
    if s:sub(i,i+3) == "null" then i = i + 4; return nil end
    return parseNumber()
  end
  return parseValue()
end

-- ===== load every structures/*.json once, at plugin init =====
local Structures = { defs = {}, byCategory = {} }
local STRUCT_DIR = "D:/powder-toy/knowledge/structures/"
local STRUCT_FILES = {  -- listed explicitly: TPT's sandboxed io has no directory-listing call
  "surface_cabin_small","surface_watchtower","surface_well","surface_campsite","surface_farm_plot",
  "surface_bridge_wood","surface_signpost","surface_ruined_wall",
  "underground_mineshaft_junction","underground_collapsed_tunnel","underground_miners_camp",
  "underground_ore_cart","underground_ladder_shaft","underground_water_cistern","underground_shrine",
  "underground_sealed_vault",
  "deep_lava_forge_ruin","deep_crystal_chamber","deep_abandoned_reactor_room","deep_bone_pit",
  "detail_rubble_pile","detail_crate","detail_barrel","detail_torch_sconce","detail_broken_pipe",
  "detail_broken_cart","detail_old_machine_husk","detail_fence_post","detail_lamp_post","detail_campfire_small",
}
for _, name in ipairs(STRUCT_FILES) do
  local f = io.open(STRUCT_DIR .. name .. ".json", "r")
  if f then
    local ok, def = pcall(function() return jsonDecode(f:read("*a")) end)
    f:close()
    if ok and def then
      Structures.defs[name] = def
      local cat = def.category
      Structures.byCategory[cat] = Structures.byCategory[cat] or {}
      table.insert(Structures.byCategory[cat], def)
    end
  end
end

-- ===== per-category placement cache (same idiom as world.lua's mineshaftAt/ruinAt) =====
-- One spacing + cache per category keeps this O(1) after the first roll, no per-frame cost.
local CATEGORY_SPACING = { surface = 240, underground = 300, deep = 440, detail = 40 }
local structCache = {}  -- structCache[category][cellIndex] = instance table or false

local function biomeEligible(def, biome)
  for _, b in ipairs(def.biomes) do if b == "any" or b == biome then return true end end
  return false
end

local function rollStructure(category, cellIdx, wx0, biome, surf)
  local pool = Structures.byCategory[category]
  if not pool then return false end
  local eligible = {}
  for _, def in ipairs(pool) do if biomeEligible(def, biome) then eligible[#eligible+1] = def end end
  if #eligible == 0 then return false end
  local totalW = 0
  for _, def in ipairs(eligible) do totalW = totalW + def.rarity end
  local r = hash3(cellIdx, 8801, 1) * totalW
  local chosen = eligible[1]
  for _, def in ipairs(eligible) do
    r = r - def.rarity
    if r <= 0 then chosen = def; break end
  end
  if category == "surface" and chosen.rest_on_solid then
    -- surfaceAt(wx0) IS the first solid row by definition, so a plain flat-ground check is vacuous here --
    -- the real hazard is a WIDE structure whose far edge hangs over a cliff/cave mouth. Reject the roll
    -- (fall through to "no structure this cell") if the ground height differs much across the footprint.
    local edge = surfaceAt(wx0 + chosen.width)
    if math.abs(edge - refY) > 3 then return false end
  end
  -- underground/deep: no solidity check needed here -- structureAt() runs before caveAt() in world.lua's
  -- dispatcher, so the cell is still "solid rock" by default at this point in the pipeline; bridges/ladders
  -- are the two exceptions and need their own predicate, not this generic one (see the prose above).
  return { def = chosen, x0 = wx0, y0 = refY }
end

local function structAt(category, wx, wy, refX, refY, biome)
  local spacing = CATEGORY_SPACING[category]
  local cellIdx = floor(refX / spacing)
  structCache[category] = structCache[category] or {}
  local cache = structCache[category]
  local inst = cache[cellIdx]
  if inst == nil then
    local cellX0 = cellIdx * spacing + 10 + floor(hash3(cellIdx, 8802, 2) * (spacing - 20))
    inst = rollStructure(category, cellIdx, cellX0, biome, refY)
    cache[cellIdx] = inst
  end
  if not inst then return nil end
  local def = inst.def
  local gx = wx - inst.x0 + def.anchor.x
  local gy = wy - inst.y0 + def.anchor.y
  if gx < 0 or gx >= def.width or gy < 0 or gy >= def.height then return nil end
  local ch = def.grid[gy + 1]:sub(gx + 1, gx + 1)
  local token = def.legend[ch]
  if token == "air" then return "" end
  if token == "keep" or token == nil then return nil end
  return MATERIAL[token] or nil
end

function Structures.at(wx, wy, surf, d, biome)
  -- surface: reference point is (wx, surfaceAt-aligned), rolled on a world-x grid
  local s = structAt("surface", wx, wy, wx, surf, biome)
  if s ~= nil then return s end
  -- underground / deep: reference point includes a rolled depth-origin per cell, so pass wy through
  -- (a fuller integration rolls a per-cell d0 the way world.lua's mineshaftAt/ruinAt already do for their
  -- own d0 fields, then reuses that same d0 as refY here instead of raw wy -- sketch left for @world since
  -- it should share world.lua's existing d0 roll idiom rather than a second one)
  local cat = (wy >= DEPTH - 350) and "deep" or ((d and d > 40) and "underground" or nil)
  if cat then
    local u = structAt(cat, wx, wy, wx, wy, biome)
    if u ~= nil then return u end
  end
  return nil
end
```

**Integration point** -- the one line that actually wires this into world generation, inside `world.lua`'s
existing `structureAt()`:

```lua
local function structureAt(wx, wy, surf, d, biome)
  if wy >= DEPTH - 60 then return nil end
  local r = ruinHere(wx, wy, d); if r ~= nil then return r end
  local m = mineshaftHere(wx, wy, d); if m ~= nil then return m end
  local s = Structures.at(wx, wy, surf, d, biome); if s ~= nil then return s end   -- <-- add this line
  return nil
end
```

That's the whole integration surface -- one new local table (`Structures`, loaded once at file scope) and one
line inside the existing dispatcher, no change to `worldGen`'s own signature or to any other hook.

**What I deliberately left as a sketch, not finished code:** the underground/deep per-cell `d0` roll (should
reuse the same idiom as `mineshaftAt`'s own `d0 = 60 + floor(hash3(...) * 500)`, not invent a second one) and
the two structure-specific placement predicates (`surface_bridge_wood`'s gap check, `underground_ladder_shaft`'s
bottom-only check). I didn't want to guess at exactly how @world wants those two integrated into functions that
don't exist in this exact shape yet -- happy to pair on it in the hub instead of guessing wrong twice.

## Loot handover (needs a small @lead decision, flagged here rather than assumed)

Only one structure ships a `loot` entry today: `underground_sealed_vault.json` (`{"x":5,"y":5,"tier":3}`).
Today's `R.chestAt()` (in `rpg.lua`) independently rolls a chest in ~45% of its own 96px cells wherever a
hollow pocket exists -- since `Structures.at` returning `""` for an air cell makes `gen(x,y) == nil` true there
too (the `gen` wrapper turns `""` into `nil`, see `rpg.lua` line 209), a sealed vault's interior *can*
coincidentally get a chest from that existing system, but it's not guaranteed, which undersells "sealed vault
**with** a chest." Recommend @lead add a small, additive, opt-in API -- something like
`R.placeChestAt(x, y, tier)` that force-inserts into `R.chests` bypassing the 45% roll -- that `Structures.at`
(or `world.lua` directly) calls once per vault instance the first time its cells are generated. Until that
exists, the vault's `loot` field is documentation of intent, not a live guarantee; flagging it explicitly
rather than quietly shipping a chest that doesn't reliably appear.
